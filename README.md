# Mita Home Assistant Add-on

Home Assistant app/add-on repository for **mita**, the server component of the [mieru](https://github.com/enfein/mieru) proxy protocol.

Features:

- Mita 3.40.0 for amd64/aarch64
- TCP transport
- Home Assistant Ingress admin UI
- add/delete users without restarting the app
- per-user LAN access settings
- per-user ClashMi subscription links
- public subscription endpoint separated from the private admin UI

## Install

1. Add this repository to the Home Assistant App/Add-on Store.
2. Install **Mita (mieru server)**.
3. Start the app.
4. Open its Web UI and manage users there.
5. Forward the Mieru TCP port on your router.
6. Reverse proxy only `/sub/*` from HTTPS to the subscription server on port 8099.

See the app documentation for the Caddy example.

## Run on Linux

Docker Engine with the Compose plugin builds the same Mita server and web UI
for Linux amd64 or arm64. The Linux service uses host networking. Mita listens on
TCP 2022, subscriptions on 8099, and the admin UI only on 127.0.0.1:8098.
Access the admin UI from another machine through an SSH tunnel:

```sh
ssh -L 8098:127.0.0.1:8098 user@linux-server
```

Before starting Mita, set `MITA_ADMIN_PASSWORD` in `.env` to a random password
of at least 24 characters, for example one generated by `openssl rand -hex 24`.
Open http://127.0.0.1:8098 through that tunnel and sign in as `admin`.
Standalone Linux disables Mita users' loopback access, including settings
restored from Home Assistant.

Host networking exposes TCP 8099 on the Linux host. Block external access
to 8099 with the host firewall and publish only `/sub/*` through your HTTPS
reverse proxy. Set
`MITA_PUBLIC_HOST`, `MITA_PUBLIC_PORT` and `MITA_SUBSCRIPTION_BASE_URL` in
Compose's local `.env` for fresh installs, or edit Public connection settings
in the admin UI. Set `MITA_POSTGRES_DSN` to enable PostgreSQL backups on a fresh install.
The connection string contains credentials. Keep `.env` private.

For a fresh install:

```sh
docker compose up -d --build
```

### Move from Home Assistant using the same PostgreSQL database

1. On Home Assistant, confirm a successful PostgreSQL backup in the admin UI.
   Starting the add-on writes a fresh snapshot. Stop the old instance once the
   snapshot is complete and before starting the replacement.
2. On Linux, set `MITA_POSTGRES_DSN` in `.env` to a connection string for the same
   database and schema. If Linux cannot resolve the HA database hostname, use an
   address reachable from Linux.
3. Restore before the first start. For an existing Linux instance, stop it and
   set `MITA_DATA_VOLUME` to a new volume name in `.env` to retain the old data.
   The restore command refuses a nonempty volume. If a restore is interrupted,
   the server refuses to start from partial data. Rerun the restore command
   on the same volume to restart that restore.

```sh
docker compose build
docker compose run --rm --entrypoint python3 mita /app/webapp.py --restore-postgres latest
docker compose up -d
```

Replace `latest` with the numeric `id` from `mita_backups` to select a specific
snapshot. Restore brings over users, passwords, subscription tokens, registered
devices, settings and saved Mita metrics. The supplied DSN is saved so the new
instance continues backing up to the same database. Snapshot archives exclude
local logs and sockets. Database log history stays in PostgreSQL.

To keep existing subscription URLs working, point their original hostname and
proxy routes at the Linux server. The database stores snapshots, so use it for
migration or recovery with one active instance. Running HA and Linux against the
same tables does not synchronize changes and mixes their snapshot histories.

## Route selected destinations through an outbound proxy

Open **Settings → Outbound** in the standalone Linux admin UI.
Save the JSON configuration, then run `docker compose restart mita`. Changes take effect after restart.
Use empty `proxies` and `rules` arrays to remove all custom routing.

Rules are evaluated in order. `domainNames` entries match the domain and its
subdomains when the client sends a hostname. If the client sends an IP, use
`ipRanges` with CIDRs. `"*"` matches all entries of that kind. A rule's
`action` is `PROXY`, `DIRECT` or `REJECT`. A `PROXY` rule references one or
more configured `proxyNames`. Unmatched destinations go directly.

Mita connects to a SOCKS5 proxy defined by `name`, `host` and `port`.
For authentication, add `"socks5Authentication": {"user": "...", "password": "..."}`
to the proxy. PostgreSQL snapshots include the outbound settings and their
credentials. The external sing-box configuration is a separate file.

### Set up the built-in sing-box on Linux

Build or update the Linux image with `docker compose up -d --build mita`.
In **Settings → Built-in sing-box**, paste one provider outbound object in
sing-box JSON format, enter the destination domains, then click **Set up
sing-box**. The Linux image already contains the executable. The button
validates the outbound, starts an authenticated local SOCKS5 listener on
`127.0.0.1:1081`, and adds a rule for the selected domains ahead of the manual
rules. Restart Mita with `docker compose restart mita` to apply the route.

The provider config and domains are included in PostgreSQL backups. Treat
these backups as confidential because the provider config may contain keys.
The **Disable** button removes the managed rule and stops the listener.
Restart Mita after disabling so it applies the remaining rules. If the
built-in sing-box process exits, Mita retries it with increasing delays up
to one minute.

#### Import GeoSite and GeoIP lists

Use **Import GeoSite / GeoIP** in the built-in sing-box form to select
sing-box source rule-set JSON files. Supported rules contain a single
`domain_suffix` (GeoSite) or `ip_cidr` (GeoIP) selector. The source files are
read in the browser and imported as editable domain and network lists.
You can also enter domains and CIDRs manually, or use an IP-only rule.

For example, this source file matches a domain and its subdomains, or a
request sent directly to an IP in the given network:

```json
{
  "version": 3,
  "rules": [
    {"domain_suffix": ["example.com"]},
    {"ip_cidr": ["198.51.100.0/24"]}
  ]
}
```

Use source JSON rather than binary `.dat` or `.srs` files. In mixed
GeoSite lists, compatible suffixes are imported and skipped exact-domain,
regex, keyword, subdomain-only, and compound rules are reported.
A list without any compatible selectors is rejected. GeoIP matches destination IPs sent by clients. Mita does not
resolve incoming domain names solely to evaluate GeoIP rules. Lists are
snapshots and can be replaced by clearing the corresponding field and
importing an updated file. Save and restart Mita to apply. The imported
destinations are included in PostgreSQL backups.

To track a GitHub list, paste up to four public GitHub file links or Raw JSON
URLs into **GitHub Geo lists**. Saving downloads and validates the files.
The running Linux service checks again every 24 hours. Successful changes
replace the downloaded entries and preserve your manually entered lists.
A failed download or invalid update keeps the last working snapshot.
Restart Mita to apply a downloaded update. Links pinned to a commit or tag
keep using that revision, while links to a branch follow its updates.
[Example GeoIP source on GitHub](https://github.com/MetaCubeX/meta-rules-dat/blob/sing/geo/geoip/cn.json).

### Optional sing-box service on Linux

Copy `sing-box/config.example.json` to `sing-box/config.json`. Keep its SOCKS5
inbound bound to `127.0.0.1:1080`. Replace the example SOCKS5 password with
a random password and use the same credentials in the Mita outbound proxy.
The example also uses placeholder VLESS settings. Replace them with your provider
settings or use a different sing-box outbound such as Shadowsocks, Trojan or
Hysteria2. Set `route.final` to that outbound’s tag. Keep endpoint credentials in this local file.

```sh
docker compose --profile sing-box run --rm --no-deps sing-box check -c /etc/sing-box/config.json
docker compose --profile sing-box up -d
```

Define a SOCKS5 proxy at `127.0.0.1:1080` in the Mita Outbound editor and
include its `socks5Authentication` credentials.
